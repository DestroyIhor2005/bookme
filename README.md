# 🏠 Інформаційна система бронювання житла "BookMe"

Онлайн-демо: https://bookme-sooty.vercel.app/

---

## 📌 Про проєкт
**BookMe** — це сучасний вебзастосунок для оренди житла. Платформа об'єднує два типи користувачів:
* **Гості** можуть шукати об'єкти, переглядати деталі, застосовувати промокоди та бронювати житло на вільні дати.
* **Власники (Орендодавці)** отримують зручну панель керування для додавання та редагування своїх об'єктів нерухомості, обробки заявок на бронювання (Підтвердження або Завершення).

---

## 🛠 Технологічний стек
* **Backend:** Node.js (ESM), Express.js
* **База даних:** MongoDB (Mongoose) + `connect-mongo` для сесій
* **Frontend:** HTML5, CSS3, Vanilla JavaScript
* **Інфраструктура:** Docker, Docker Compose
* **Тестування:** Jest

## 🚀 Швидкий запуск (Docker)

Попередні умови
- Встановлений Docker Desktop (Windows) або Docker Engine + Docker Compose (Linux / macOS).
- Git (для клонування репозиторію).

Кроки запуску
1) Клонування репозиторію та перехід у папку проекту

```bash
git clone https://github.com/DestroyIhor2005/bookme
cd bookme
```

Якщо GitHub створить іншу назву папки після клонування, просто виконайте `cd` у цю папку.

2) Підготовка `.env`

Відкрийте `.env` і переконайтесь, що там є такі змінні (для Docker):

```
MONGODB_URI=mongodb://mongo:27017/House_Booking?retryWrites=true&w=majority
SESSION_SECRET=будь-який_довгий_секрет
PORT=3000
NODE_ENV=production
```

Цей файл потрібен, щоб застосунок знав, куди підключатися до бази даних і який секрет використовувати для сесій.

Для запуску без Docker на локальній машині використовуйте:

```
MONGODB_URI=mongodb://127.0.0.1:27017/House_Booking?retryWrites=true&w=majority
```

3) Запуск у Docker

Після того як `.env` вже створений, запустіть весь проєкт однією командою. Вона підніме базу даних, застосує міграції і стартує застосунок:

```bash
docker compose up --build -d
```

Виконайте цю команду щоб наповнити базу даних стартовими даними:

```bash
docker compose run --rm app npm run seed
```

Після цього контейнер з сайтом буде працювати у фоновому режимі, а сам застосунок відкриватиметься через браузер.

4) Перевірка стану контейнерів

Ця команда показує, чи запустились усі сервіси проєкту: база даних, міграції та сам сайт.

```bash
docker compose ps
```

У списку мають бути активні контейнери без помилок.

5) Перевірка логів міграцій

Ця команда показує, чи міграції виконалися без помилок і чи створилися початкові дані для тестування.

```bash
docker compose logs migrate --tail=200
```

Якщо все добре, у логах буде повідомлення про успішне застосування міграцій.

6) Перевірка доступності сервера

Відкрийте у браузері:

`http://localhost:3000`

Якщо сторінка відкрилась, сервер працює. За бажанням можна ще перевірити це через термінал:

PowerShell:
```powershell
(Invoke-WebRequest -UseBasicParsing http://localhost:3000).StatusCode
```

Bash (curl):
```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
```

7) Запуск міграцій вручну, якщо вони не стартували автоматично

Ця команда окремо запускає тільки міграції бази даних:

```bash
docker compose run --rm migrate
```

9) Зупинка та очищення

Якщо потрібно просто зупинити всі контейнери:

```bash
docker compose down
```

Якщо потрібно ще й видалити дані бази даних:

```bash
docker compose down -v
```

Поширені проблеми і рішення
- Якщо порт 3000 зайнятий — змініть `PORT` у `.env` і перезапустіть `docker compose up --build -d`.
- Якщо міграції не застосувалися — перегляньте логи `migrate` та `app`: `docker compose logs migrate` і `docker compose logs app`.
- Помилки npm під час збірки образа: спробуйте збілдити з чистою кеш-пам'яттю: `docker compose build --no-cache`.

Додатково (опціонально)
- Переглянути логи в реальному часі:

```bash
docker compose logs -f app
```

+- Запустити тести в контейнері:

```bash
docker compose run --rm app npm test
```

## 📝 Як користуватись застосунком

### Роль "Гість"
1. Перейдіть на головну сторінку.
2. Пройдіть коротку реєстрацію або увійдіть в акаунт.
3. Оберіть житло з каталогу, вкажіть дати заїзду/виїзду та натисніть "Забронювати".
4. Слідкуйте за зміною статусу вашої заявки в розділі "Особистий кабінет".

Також Гість може опублікувати і своє житло. Якщо Гість публікує своє житло, то йому будуть доступні функції які є у Власника.

### Роль "Власник"
1. Увійдіть в акаунт та перейдіть у "Особистий кабінет".
2. На вкладці "Об'єкти" ви можете додати нову квартиру чи будинок до каталогу.
3. На вкладці "Бронювання" з'являтимуться запити від гостей. Ви можете Підтвердити бронювання або позначити його як Завершене (коли гість виїхав).

## 💬 Чат із власником

- Опис: у проєкті реалізована опція обміну повідомленнями між гостем і власником (локальний чат). Чат активується для облікового запису, якщо в профілі вказано номер телефону лише з кодом країни який є доступний при виборі у вікні налаштування профілю, в яке вам пропонує перейти після реєстрації — це умовна перевірка контакту для демонстрації функції.
- Як працює: повідомлення зберігаються у колекції `ChatMessages` на сервері; UI чату відображається на сторінці бронювання та в панелі власника. Повідомлення синхронізуються між сесіями під час роботи застосунку.
- Як перевірити:
	1. Після реєстрації та збереження даних у профілі, перейдіть у каталог, оберіть житло, на сторінці бронювання ви побачите кнопку Чат з власиком, натисніть на неї, напишіть тестове повідомлення та натисніть надіслати.
	2. Перейдіть в особистий кабінет, на панелі користувача буде опція Чати, перейшовши туди ви побачите чат з власником житла та можете перейти у переписку. Також через переписку ви можете редагувати або видаляти свої повідомлення.
	3. Перейдіть у профіль власника, ви побачите що вам прийшло сповіщення, після чого вам потрібно так само перейти у особистий кабінет --> чати, і вже там від лиця власника відповідати користувачу.
- Примітка з приватності: у демонстраційному проєкті номер телефону використовується лише як тригер активації чату.
